# 期末大作业实施计划初稿（课堂八当堂完成）

> 说明：以自主实践作品「昆明天气信息中心」为原型与起点。期末大作业统一题目与六条最低功能要求
> 以当堂发布的正式文档为准，发布后按正式文档核对并微调本计划。

## 表一：任务分解

| 任务 | 技术 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| 1. 确定最终题目与范围清单（必须 / 可选 / 不做） | 任务管理 | 必须 | 写出一页范围说明，每个模块有明确"做 / 不做"结论 |
| 2. 数据集定稿：扩展天气数据至 30 天以上并校验格式 | JSON | 必须 | data.json 通过格式校验；空数据 / 格式错提示可复现 |
| 3. 页面结构与统一导航改造 | HTML + Bootstrap | 必须 | 全部模块从导航可达；375px 下导航折叠正常 |
| 4. 样式与三档响应式打磨 | CSS + Bootstrap 栅格 | 必须 | 375 / 768 / 1200px 三档无横向滚动，截图留证 |
| 5. 交互模块扩展：多条件组合筛选 + 表单校验 | jQuery 事件委托 | 必须 | 非法输入有提示；筛选后无残留旧数据；Console 无报错 |
| 6. 可视化模块扩展：第三类图表（如温度范围条形图） | ECharts 或 Chart.js | 必须 | 图表有标题、单位、数据来源；窗口缩放自适应 |
| 7. 三维模块增强：建筑点击高亮与信息展示 | Three.js | 必须 | 点击建筑显示名称信息；离开页面渲染循环停止 |
| 8. 数据本地保存：用户查询偏好记忆 | localStorage（课堂五） | 可选 | 刷新后筛选条件保留；清空浏览器数据后正常 |
| 9. 可访问性专项：Tab 走查 + 对比度检查 | HTML 语义 | 可选 | 纯键盘可完成主要操作；无"仅颜色传达信息"项 |
| 10. 引入 React / Vue / 后端等未讲授框架 | — | **不做** | 防止范围膨胀与超纲（指南红线） |

## 表三：风险清单

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 三维模块增强（任务7）耗时超出预期，挤占测试时间 | 期末验收核心项未打磨，质量下降 | 任务7限定在 9月28—30日完成，超时即降级为"仅保留课堂七水平"，优先保证任务5/6质量 |
| 数据集扩展后图表坐标轴错乱（如降水量 0 值过多、日期跨月） | 图表可读性差，可视化正确性扣分 | 扩展数据当天即渲染验证；为日期排序写单独处理函数并留测试用例 |
| file:// 与服务器两种打开方式行为不一致（fetch 限制） | 验收现场双击打不开，误判为故障 | 保留 weather.js 兜底并显示明确提示；README 写清两种运行方式，提交前各测一遍 |
| 现场抽查讲解时对某段代码（如 Chart.js 配置）解释不清 | 视同非本人完成，成绩风险 | 每完成一个模块，用自己的话写三句"这段在做什么"，讲解前通读一遍 |
| 浏览器兼容差异（Chrome 与 Edge 表现不同） | 某浏览器白屏或样式错乱 | 按质量清单在 Chrome 与 Edge 各至少打开一次并截图 |

> 完成标准：任务到模块到天；每条风险有具体应对（"可能来不及"不算）。
